# 题目笔记云端启用

在当前网站所连接的 Supabase 项目中打开 **SQL Editor**，粘贴并执行
`migrations/20260930_question_notes.sql` 的完整内容。执行成功后刷新网站并正常登录，即可使用题目笔记。

本次迁移只新增 `question_notes` 表及其索引、权限策略和更新时间触发器，不修改题库和 `optics_progress`。可重复执行，不删除既有笔记。

## 数据与权限

- `id` 为 UUID；`user_id` 关联 `auth.users.id`。
- 当前题库存储在 JSON 中，真实 `question.id` 是字符串，例如 `geom-ch1-xuan1`，因此 `question_id` 使用 `text`，不是界面题号。笔记表不复制原题内容。
- `(user_id, question_id)` 唯一；同一用户每题一份笔记。
- RLS 使用 `auth.uid() = user_id` 控制读取、新增、更新和删除。匿名用户无权限；用户只能更新笔记正文，不能改归属、题目 ID 或时间戳。
- 更新时间由数据库维护。多窗口保存发生冲突时保留草稿，用户查看最新云端内容并确认后才能覆盖。

## 使用

当前题目下方的“题目笔记”可直接编辑；侧栏“云端记录”下方的“题目笔记”按修改时间列出记录。在同一浮层中查看原题、编辑笔记和确认删除。

Ctrl + Enter 保存，Esc 或关闭按钮收起。未保存文字仅保留在本次页面内存中，刷新或切换账号后清除；已保存内容只从 Supabase 读取和写入。保存失败不会关闭编辑器，也不会显示“已保存”。

## 验证范围

本地 Chrome 使用隔离 Supabase 测试数据验证了两个入口同步、增改删、刷新读取、失败保留草稿、并发冲突、主题和竖屏显示；本地 PostgreSQL（PGlite）执行实际迁移并验证重复执行、唯一约束、账号 A/B 隔离及匿名拒绝。

这些测试没有写入正式 Supabase 项目。本版尚未执行生产迁移；SQL 执行后，应再用正式账号保存一条笔记、刷新检查，并用第二个账号验证隔离。
